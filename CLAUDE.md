# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm install
npm run dev       # Vite dev server (http://localhost:5173)
npm run build     # type-check (tsc) then production build to dist/
npm run typecheck # tsc only
npm run preview   # serve the built dist/
```

There are no tests, linter, or formatter configured; `tsc` (strict) is the only static check and gates `npm run build`. Verification is visual: run the dev server and move the pointer over the canvas.

Pushing to `main` deploys to GitHub Pages via `.github/workflows/deploy-pages.yml` (Node 22, `npm ci && npm run build`). `vite.config.js` sets `base` to `/<repo>/` only when running in GitHub Actions, so local builds use `/`.

## Architecture

A fullscreen, UI-free datamosh sandbox: a simplified inter-frame video decoder running in WebGL2 via three.js. Host code is TypeScript in `src/`: `config.ts` (tuning), `gl.ts` (renderer, `pass()`, `draw()`, `target()`, typed `Uniforms`/`Pass`), `passes.ts` (every pass's material and uniforms), `targets.ts` (internal size and render targets), `sources.ts` (`Source` interface, procedural and video sources), `pointer.ts`, `decoder.ts` (`Decoder`: allocation, `setSource`, `step`, `present`), `debug.ts`, `drop.ts`, and `main.ts` wiring them together with the rAF loop. The actual image processing is in `src/shaders/`. See README.md for the effect's design rationale.

**Pass pipeline.** The decoder draws a single fullscreen quad with a swapped `ShaderMaterial` per pass (`pass()` / `draw()`). Every fragment shader is prefixed with `common.glsl` at build time (imported via Vite `?raw` and string-concatenated), so helpers like `rgb2ycc`, `hash12`, `isInterAt`, `pixelMv`, `basis`, the `MB`/`SB` defines and the `fragColor` output are available in every `.frag` without declaring them. `uBasis` (the 8×8 DCT basis) is injected into every pass's uniforms. A new uniform goes in both the pass's type parameter and its initial values in `passes.ts`. Shaders are GLSL3 (`#version` is added by three.js).

**Per-step order** (`Decoder.step()` in `decoder.ts`), each writing to its own render target:
1. `source.draw()` → `src[0]` (clean source frame; `src` ping-pongs so `src[1]` is the previous frame). The source is `createProcedural()` (`background.frag`) or a `videoSource()` (`video.frag`, cover-cropped `VideoTexture`) created by dropping a video file on the page. `setSource()` swaps sources like a datamosh cut with the new clip's I-frame removed: it keeps `ref`, redraws `src[1]` so the first step sees no motion, and flags `cutPending` so the next `blocks.frag` step sets every block's heat to 1 (`uCut`, all inter)
2. `flow.frag` → `flow` (one texel per macroblock: pyramidal Lucas–Kanade motion of the background between `src[1]` and `src[0]`, coarse-to-fine over 4 mip levels with 2 warped iterations each, so it tracks motion up to roughly 15 px/step; `rg` = px/step, `b` = speed)
3. `mask.frag` → `mask` (one texel per macroblock, `r` = pointer zone strength: a soft disc minus drifting simplex noise scaled to 0–0.5)
4. `blocks.frag` → `state` (ping-pong, one texel per 16×16 macroblock: `r` = melt latch, `g` unused, `b` = heat, `a` = random seed). The pointer's heat scales with its speed (`params.speedRef`) and the mask, so a still pointer does nothing. Heat has no time decay and only drains where `flow` speed exceeds `params.healSpeed`. The melt latch sets on a seeded share (`meltFrac`) of inter blocks whose last-step offset exceeds `meltMv`, and clears when the block goes intra
5. `sub.frag` → `sub` (ping-pong, one texel per 8×8 sub-block: `rg` = the partition's pointer offset in internal px, `b` = the macroblock's partition code 0..3 = 16×16 / 16×8 / 8×16 / 8×8, identical in all four siblings). Each sub-block gets its own vortex target plus a seeded twist (`subShear`, `subTwist`); the code is chosen by rate-distortion (`J = E + λ·bits`, bits {0,1,1,3}, λ from `lamLo`..`lamHi` by block seed, hysteresis toward last step's code, forced to 0 outside the zone). Each group then relaxes its mean previous offset (decays by `params.mvRelax` per step, or `mvRelax·bloomRelax` on a `bloomFrac` share of macroblocks) and mixes toward its mean target. All siblings must compute bit-equal group values. A pixel's actual vector is `pixelMv()` in `common.glsl`: that offset plus `-flow`, so every block always follows the measured background motion exactly; reconstruct and present read `flow` for this
6. `dctRows.frag` → `tmp`, `dctCols.frag` → `coef` (separable quantised 8×8 DCT of `cur - prev`, one texel per coefficient laid out block-locally), then `idctRows.frag` → `tmp` (first half of the inverse; `tmp` is reused because `coef` is complete before it is overwritten)
7. `reconstruct.frag` → `ref` (ping-pong feedback: MC from previous decoded frame + the last 8 IDCT taps for inter pixels, clean source for intra). Fractional vectors are rounded with the per-step `uPhase` dither (shared by all blocks), so sub-pixel motion advances in whole-pixel jumps. Melted blocks instead use a 16-tap Catmull-Rom `refCubic()` of `ref` that resets the chroma magnitude to the taps' weighted mean (so repeated interpolation doesn't desaturate towards brown), warped by a bilinear `texture()` of `sub` when code 0, plus a write dither; colour drift (`chromaLag` on the pointer offset only, `dcDrift`) applies to melted pixels only. Code-3 partitions within `smearBand` heat of healing blend in their neighbour's edge (`smear`), and `resBloom` applies to a share of all inter partitions. `ref.a` is each pixel's mosh margin (heat minus threshold when it was hot; 0 = clean, and the sources write alpha 0). Cold pixels do an honest MC with `-flow` and no residual: if the fetched alpha minus the heal rate stays > 0 they keep the carried mosh, otherwise they take the clean source. This is what lets mosh travel with the background out of the hot blocks

`present.frag` then draws to the screen, showing `ref` wherever `ref.a > 0` and the filtered source elsewhere. Pressing `d` toggles a debug overlay: an fps readout (DOM element, `.fps` in `style.css`) and, in `present.frag`, the `mask` shaded translucent black with a white arrow per masked partition group showing its motion (`-mv`, since `mv` is a fetch offset), and 1 px partition edges on masked inter blocks. Ping-pong buffers are swapped with `array.reverse()` after each write, so index `[0]` is always "latest" after a swap — keep that invariant when adding passes.

**Key invariants.**
- The decoder runs at a fixed internal resolution (short side `SHORT_SIDE = 384`, long side rounded to a multiple of `MB = 16`), independent of screen size. Pointer coordinates are converted to this space with origin bottom-left (`Pointer.toInternal`). Render targets are reallocated only when the internal size changes.
- Inter vs. intra per pixel is decided by `isInterAt()` in `common.glsl` (the macroblock's heat above its partition group's seeded threshold); it is the only inter test, and the DCT passes, reconstruct and the melt latch must all use it (present decides by `ref.a`, which reconstruct derives from it). An 8×8 DCT block always lies inside one partition. The helpers take already-fetched texels, so `common.glsl` declares no samplers.
- All render targets are `RGBA16F` (`HalfFloatType`) for iOS renderability — don't switch to 32-bit float. Most use `NearestFilter` and `texelFetch`. `src` is linear and mipmapped (`generateMipmaps`) because its mip chain is the image pyramid for `flow.frag`. `sub` is linear only for the `texture()` vector warp in reconstruct's melt path; every other read of it is `texelFetch`.
- The decoder steps once per source frame: `frame()` calls `step(dt)` for each duration returned by `source.poll()`. The procedural source runs at a fixed `STEP = 1/60` (max two steps per rAF frame); a video source steps once per presented frame (`requestVideoFrameCallback`, `dt` from `mediaTime`). Tuning constants (`params` in `config.ts`, passed as uniforms via `passes.ts`) are per decoded frame and deliberately not rate-scaled; only the pointer's smoothing, velocity clamp and `speedRef` are scaled by `k = dt / STEP`.
- Source frames are display-encoded values with no colour conversion anywhere in the pipeline; the video texture uses `NoColorSpace` to match.
